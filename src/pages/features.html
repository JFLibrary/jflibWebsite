Interface

What people see and touch in your app.

Widgets and layout

An app describes its interface in one function. JFLib handles layout, input, focus and drawing.

Buttons
Standard, accent, icon and split buttons.
Choices
Check boxes, radio buttons and switches.
Values
Sliders and progress bars.
Text input
Text fields, password fields and number boxes.
Lists and tabs
Lists, tabs and scroll areas.
Menus and dialogs
Menus, context menus and dialogs.
Toolbars and ribbons
Plain toolbars and full Office ribbons.
Grid box
Lay widgets out in rows and columns.
Docking
Panels in tab groups and floating tool windows, with drop markers while dragging. The layout is kept.
Popups and tooltips
They may leave the window, like native ones.
Scaling
Sizes are device-independent, so an interface stays sharp on every display.

Data views and app shells

The parts a real business app is made of, drawn by every style.

Virtual grids
Large tables with sorting and multiple selection.
Trees
Nested data, also with check boxes.
Navigation panes
The side menu of a modern app, with groups and badges.
Command bars and splitters
The frame around your content.
Wizards
Step-by-step flows with a visible position.
Charts
KPI cards with sparklines, line charts, stacked bars and donuts.
Toasts
Short messages that do not interrupt.
Date and time inputs
Ready-made fields for dates and times.
Diagram canvas
Nodes, ports, straight, curved and right-angled edges, grid snapping and a minimap.
Terminal
A terminal widget for consoles and logs.

Editors

Finished editors you can place in your app like any other widget.

Rich-text editor
A formatting toolbar, headings, character formats, colours, fonts, lists and quotations, with HTML in and out.
Code editor
Highlighting for Rust, JSON, INI, TOML and Markdown, line numbers, find and replace. Stays fast with 100,000 lines.
Markdown and HTML viewer
Shows documents with selection, links, images, tables and code blocks.
Undo history
Undo and redo for your app's own documents.

Look and text

How your app appears, reads and adapts to the person using it.

Rendering

JFLib draws everything itself, so an app looks the same on every system.

Own software renderer
Text, paths, shapes, gradients, image compositing and effects.
Scalable interfaces
Any scale, on any display.
Light and dark
Both themes, following the system or your choice.
SVG images and icons
Drawn by JFLib's own rasterizer, sharp at every size.
Image viewer
A widget with zoom and pan.
Animation
Easing curves for smooth movement, and reduced motion when the system asks for it.

Styles and themes

The style draws the widgets, so one interface can take on a different look without changing your logic.

Ready-made styles
WinUI, macOS, KDE, Classic, jfOffice, BackupCraft and netlab.
Independent of the system
The macOS style can run in a Windows app.
Change while running
Light and dark, accent colours and scaling switch at run time. An app that links several styles can switch between them too.
Your own theme
A small INI file sets colours, corner radii, spacing, control heights and type, over any style.
Your own style
A documented contract for writing a new style.

Text and fonts

Text that works for real documents and real languages.

OpenType shaping
Complex scripts, ligatures and bidirectional text.
Font fallback
Missing glyphs come from other fonts, with font aliases and fonts per language.
Font picker and dialog
Search the installed fonts and preview the choice.
Line breaking
Unicode grapheme, word and line segmentation, and hyphenation.
Subpixel smoothing
Sharp text on ordinary displays.
Spell checking
Hunspell dictionaries or the Windows spell checker, with suggestions and a personal dictionary.
Input methods
On Windows, Wayland and X11.

Accessibility

Follows the system's settings by default.

Screen readers
UI Automation on Windows, AT-SPI2 on Linux, an ARIA tree in the browser and accessibility nodes on Android.
High contrast
A high contrast theme that follows the system.
Text size
A text scale separate from the UI scale. Icons keep their size.
Accent colour and reduced motion
Taken from the system.
Full keyboard operation
Focus groups, F6 through panes and the menu key everywhere.
Screen magnifiers
The caret position is reported so a magnifier can follow it.

System

Your app behaves like it belongs on the desktop.

Drag and drop
Text, HTML, URLs, images and files, between widgets and to and from other programs.
Notifications and tray icon
System notifications and a notification-area icon.
Taskbar
Progress, badges and jump lists.
File types and URL schemes
Your app opens its own files and links.
One instance per app

Start at login, stay awake
Start with the session and keep the system awake when needed.
Monitors

Global shortcuts
Keys that work while your app is in the background.
Screen tools
Pick a colour anywhere on the screen and take pictures of the screen.

Sound

Output streams
With a target latency, over WASAPI, the PulseAudio protocol that PipeWire serves, WebAudio and AAudio.
Short sounds
WAV and Ogg Vorbis files, mixed together.
System sounds
The system's own sounds for events and message dialogs.

AI agents

JFLib is designed to be used by AI agents, so an agent can build an app, run it and check the result by itself.

# see
--shot build/app.png --size 1000x800
# act
--script tests/smoke.uis
--agent-json
--agent-mcp
# check
python build_rs.py test hello
See
Screenshots and widget dumps show an agent what is on screen.
Act
Scripts, or JSON-RPC and MCP over standard input and output.
Check
Expectations in scripts and a test command for every app.
Off by default
No language model runs inside your app, and the endpoint stays closed until you switch it on at startup.

Foundation

What the library runs on, and how it is built.

Platforms

Native windows, the browser host and the Android adapter use the same widgets and renderer.

Windows
Native x86-64 app with desktop integration.
Linux
Native x86-64 app, on Wayland or X11, picked at startup.
Android
Native APK for Android 8 and later. So far through the Pocket Gallery, with fewer desktop services.
Browser
WebAssembly with scalar, SIMD and threaded builds, tested on Chromium and Firefox. Native plugins and system services are more limited here.
macOS and iOS
Through the browser for now. There is no native build yet.

GPU

Direct access to the graphics card, for programs that need more than an interface.

Screenshot planned:
a 3D scene from the GPU tests
Explicit API
Compute shaders, rendering with a depth test, indirect draws, timestamps and swapchains, in the style of Vulkan and WebGPU.
WGSL shaders
Checked and compiled to SPIR-V by the library itself.
Available today
Vulkan on Windows. The widgets still rasterize on the CPU. On Windows, the GPU takes over output, layers, images and canvases.
Planned
Vulkan on Linux and Android, WebGPU in the browser and later Metal.

Foundation

How the library itself is put together.

#![no_std]
#![no_main]
#![deny(unsafe_code)]

extern crate alloc;
use ui::*;
no_std
The Rust code uses core and alloc, with no GUI framework underneath.
Direct builds
A Python script calls rustc directly. Complex text shaping adds a small pinned Cargo project with HarfRust, linked statically.
Modular
50 crates with safe APIs for your app.
Contained unsafe
It stays inside the runtime, platform, SIMD and plugin layers.
Open licences
MIT or Apache 2.0, at your option.
