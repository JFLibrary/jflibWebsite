title: JFLib Live Inspector description: The live inspector of the JFLib GUI library: the widget under the pointer, the widget tree, frame costs, colours, editing the look while the app runs, and the line of code behind every widget. ---
--inspect · Ctrl+Shift+I · F12

Look inside a running app.

The live inspector shows which widget is where, how the layout nests, what each frame repainted and what it cost. In a development build it also changes the look while the app runs and takes you to the line of code that built a widget. It is part of every JFLib app, and closed it costs nothing.

Read the developer guide All developer tools

Point, click, know.

Press Pick in the inspector, then click any widget in your app. The click selects instead of acting, and the tool window jumps to the widget: its kind, id, label, rectangle, value, state, layer and window, a selector for your test scripts, and the file and line where your code created it.

Three ways to open it.

The inspector lives inside the library, so every app has it without a line of extra code. Nothing is recorded or drawn while it is closed: the frames are byte for byte those of an app without it.

At the start

hello --inspect

Opens the inspector together with the app.

With a key

jfgui_INSPECT=1
# then Ctrl+Shift+I or F12

Arms it, so the hot keys open and close it while you work. You can choose other keys.

From code

ui.inspect_show(true);

For a debug menu in your own app.

An overlay in every window.

The widget under the pointer gets an orange outline and a tag with its kind, id, label, size and state. The selected widget is outlined in blue. The overlay is drawn after your app, outside its draw lists, so your app's repaint regions stay its own.

A tool window with four tabs.

The inspector's own window never takes the keyboard by itself, and it never shows up in its own tree, overlay or pick. Its selector line copies straight into a test script.

Change the look while it runs.

In a development build, the inspector edits the running app through what already exists: no API to call and no state structure to follow. Try another style, dark mode or high contrast, an accent, a language, a scale, rounder corners or another font, and see it at once.

  • Every change is marked, with its own reset button and a list of old and new values.
  • Undo and redo, also for a whole slider drag as one step.
  • Save your changes as a theme file the app can load.
  • Copy what you changed, as theme lines and as code.
  • Operate clicks, drags, types or sets a value on the selected widget, as input. Your app's own values are never written behind its back.

From the widget to your code.

The Widgets tab names the file and line where your app built the selected widget. Open in editor starts VS Code, CLion or the editor you name, at that line. A composite widget such as a number box or a menu reports your call, not the library's inner one.

Release builds leave this out completely, so they carry no file paths and run the same code as without the feature. Starting the editor follows your app's permission manifest like any other program it starts.

# the inspector's Widgets tab
Kind      radio
Label     Green
Selector  radio:"Green"
Source    apps/gallery/main.rs:215
          [ Open in editor ]

# your editor, set once
jfgui_EDITOR="code -g {file}:{line}"

Tested like everything else.

The inspector runs headless in .uis test scripts too: open it, pick, select, check the overlay and the selector, edit the look and undo it. A script can even prove that a closed inspector changed nothing at all.

With hot reload, the inspector keeps its tab, options and selection across every rebuild. A failed build keeps the old version running and shows the error at the top of the inspector.

inspect arm
key f12                         # the hot key opens it
inspect pick
click "Standard"                # selects, the app sees nothing
inspect expect selected button:"Standard"
inspect set radius 8
inspect expect changes 1
inspect undo
key f12                         # closed again
inspect expect same              # byte for byte as before
inspect expect idle              # and no work since
