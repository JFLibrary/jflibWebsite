What's coming next.

JFLib is under active development. These are the big steps ahead. There are no dates, and the order can still change.

Done Next Planned
In progress

GPU support

A GPU layer inside the library, for interfaces, 2D CAD and 3D games, with one API on every platform. The widgets keep being drawn on the CPU, so they stay pixel-identical. The GPU takes over output, layers, images and canvases.

  1. GPU layerCompute shaders, depth-tested rendering and swapchains, with Vulkan on Windows, Linux and Android.
  2. Shader compilerWGSL to SPIR-V, inside the library.
  3. Interface on the GPUOutput with vsync, layers and canvases that pan and zoom, on Windows, Linux and Android.
  4. BrowserThe same layer on WebGPU, with shaders as WGSL.
  5. 3D engine and CADA 3D engine core and a 2D renderer for CAD.
  6. MetalThe GPU layer on Mac and iPhone, which draw on the CPU until then.
In progress

Windows and Linux on ARM

Every app that runs on Windows and Linux today will also run natively on 64-bit ARM: on Windows laptops with ARM chips, and on Linux boards and servers. Apps are still built on an x86 PC, and the x86-64 builds stay exactly as they are. Android already runs on ARM.

  1. Build setupARM64 as a second target, built on the same x86 PC.
  2. SIMD on NEONThe vector code on ARM, with exactly the results of x86.
  3. EmulationToday’s x86-64 apps already run on Windows on ARM: 84 of 85 test scripts pass.
  4. RuntimeMemory, threads, maths and system calls on Linux ARM64.
  5. Linux on ARMThe platform layer, plugins and modules as native ARM64 code.
  6. Windows on ARMNative ARM64 apps for Windows, without emulation.
Done

Native macOS and iOS

Since November 2026, JFLib apps run natively on Macs with Apple silicon and on the iPhone, with the same Rust widgets and the same renderer. They are built on a Mac.

  • macOS 13 and later: AppKit windows, the menu bar, Dock, notifications and system services
  • A signed and notarized .dmg, and updates of the whole app
  • iOS 16 and later: touch, Apple Pencil, keyboards, sensors, files and the clipboard
  • Next: Metal for the GPU layer, and VoiceOver
Planned

3D engine

An engine core on top of the GPU layer, grown from the test scene that already runs today.

  • Scenes, meshes and materials
  • Light and shadows
  • Visibility on the GPU, and instancing
  • glTF import
  • Later: animation, large worlds, physics and tools
1.71 msper frame for one million moving cubes at 1080p, with the GPU deciding what is visible and writing its own draw calls.
90 msfor the same scene with one draw call per object.

JFLib's GPU test scene on a GeForce RTX 2070 SUPER and a Ryzen 5 3600.
