Pruebas que se leen como instrucciones.

Un script .uis usa tu app como lo haría una persona. Hace clic, escribe, arrastra, desliza y pulsa teclas, y luego comprueba qué ha pasado. Ejecuta la app real sin ventana, con un reloj virtual, así que cada ejecución termina con el mismo resultado y los mismos píxeles, en tu máquina y en CI.

Mira un script en acción El lenguaje en la guía

Una línea, un paso.

Este script rellena parte de la Galería de funciones. Cada imagen muestra cómo se veía la app justo después de esa línea. Las líneas que empiezan por expect son las comprobaciones. Haz clic en una línea para saltar a ella.

  1. click #700
  2. type "Ada Lovelace"
  3. expect #700 text "Ada Lovelace"
  4. click "Option A"
  5. expect checkbox:"Option A" unchecked
  6. click "Blue"
  7. expect radio:"Blue" checked
  8. drag 105,446 186,446 12
  9. expect #140 value 84
  10. key tab up up
  11. expect #141 focused
  12. expect #141 value 14
  13. theme dark

Por qué funciona tan bien.

La app real

Sin mocks y sin compilación de prueba. El script le pasa a la app compilada los mismos eventos que le pasaría la plataforma.

Sin ventana

La app dibuja en memoria. No se abre ninguna ventana, nada te roba el teclado, y también funciona en un servidor sin escritorio.

Determinista

El tiempo es un reloj virtual en fotogramas de 16 ms. Los temporizadores y las animaciones lo siguen, así que una ejecución nunca espera ni falla al azar.

Selectores legibles

Nombra un widget por su etiqueta, por tipo y etiqueta, por id o por un punto. Unas reglas claras deciden qué pasa cuando una etiqueta aparece dos veces.

Fallos claros

FAIL line 9: … indica la línea y lo que se encontró en su lugar. El script continúa, y el código de salida se lo comunica a CI.

Un lenguaje para todo

Los mismos scripts funcionan en Windows y Linux, y también controlan el inspector.

Todo lo que puede hacer una persona.

Y algunas cosas que una persona no puede: un script puede soltar archivos desde otro programa, suspender la app, pasarle lecturas de sensores o perder la GPU, todo sin un dispositivo real.

Comprueba lo que importa, hasta el píxel.

Las aserciones leen estados, valores, textos y rectángulos de los mismos registros que ven los lectores de pantalla y el inspector. Cuando importan los píxeles, un script compara un punto, un área o toda la ventana con una imagen anterior, byte a byte.

  • Estados: exists, focused, checked, disabled, selected, open, pressed y más.
  • Valores, rangos, textos y rectángulos en píxeles independientes del dispositivo.
  • Tokens del tema, el estilo en uso, los sonidos solicitados y las advertencias impresas.
  • --verify-dirty compara cada redibujado parcial con uno completo, para que ningún píxel olvidado pase desapercibido.
expect button:"Send" disabled
type "Hi"
expect button:"Send" enabled
expect #140 value 40..60
expect text:"Saved" exists
expect #9 rect * * * 36
expect pixel 12 40 #0067C0
expect token accent_text #FFFFFF

shot before.png
theme dark
theme light
expect same before.png       # byte a byte

Presupuestos de fotograma como pruebas.

bench cronometra fotogramas reales mientras las cosas se mueven: una animación, un arrastre, una serie de giros de rueda. Muestra la media, la mediana y el peor fotograma, y con un límite falla cuando la mediana supera el presupuesto. Tres intentos compensan una máquina de compilación ocupada.

Así es como la prueba de rendimiento de JFNetworker desplaza, amplía y arrastra una red de 500 dispositivos y 800 cables a 1920 × 1080.

# 300 fotogramas de un arrastre, como máximo 16,6 ms cada uno
bench 300 drag #50 900,500 16600

# desplazamiento suave
wheel 500,400 -360
bench 60 anim 16600

Cada animación de este sitio es un script.

Los GIF y las capturas de este sitio no se grabaron a mano. Un script lleva cada app al estado adecuado y toma una imagen tras cada paso, sin ventana. Vuelve a ejecutarlo después de un cambio y las imágenes se actualizan solas.

Míralas en la página de funciones

Cada app nueva empieza con una prueba que pasa.

cargo jflib new crea tests/smoke.uis junto a tu código. cargo jflib test compila la app y ejecuta cada script de tests/. Una primera línea #!args pasa argumentos al programa, y dump imprime el árbol de widgets con ids y posiciones cuando escribes un script nuevo.

El inspector muestra el selector de cualquier widget que señales, listo para pegar.
