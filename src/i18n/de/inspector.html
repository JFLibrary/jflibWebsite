title: Live-Inspektor von JFLib description: Der Live-Inspektor der GUI-Bibliothek JFLib: das Widget unter dem Mauszeiger, der Widget-Baum, Frame-Kosten, Farben, das Aussehen ändern, während die App läuft, und die Codezeile hinter jedem Widget. ---
--inspect · Ctrl+Shift+I · F12

Schau in eine laufende App.

Der Live-Inspektor zeigt, welches Widget wo ist, wie das Layout verschachtelt ist, was jeder Frame neu gezeichnet hat und was das gekostet hat. In einem Entwicklungs-Build ändert er außerdem das Aussehen, während die App läuft, und bringt dich zur Codezeile, die ein Widget erzeugt hat. Er steckt in jeder JFLib-App und kostet nichts, solange er geschlossen ist.

Zum Entwicklerhandbuch Alle Entwicklerwerkzeuge

Zeigen, klicken, wissen.

Drück im Inspektor auf „Pick“ und klick dann auf irgendein Widget in deiner App. Der Klick wählt aus, statt etwas auszulösen, und das Werkzeugfenster springt zum Widget: Art, ID, Beschriftung, Rechteck, Wert, Zustand, Ebene und Fenster, ein Selektor für deine Testskripte sowie Datei und Zeile, in der dein Code es erzeugt hat.

Drei Wege, ihn zu öffnen.

Der Inspektor steckt in der Bibliothek, also hat ihn jede App ohne eine Zeile zusätzlichen Code. Solange er geschlossen ist, wird nichts aufgezeichnet oder gezeichnet: Die Frames sind Byte für Byte die einer App ohne ihn.

Beim Start

hello --inspect

Öffnet den Inspektor zusammen mit der App.

Per Taste

jfgui_INSPECT=1
# dann Ctrl+Shift+I oder F12

Schaltet ihn scharf: Die Tastenkürzel öffnen und schließen ihn dann, während du arbeitest. Du kannst andere Tasten wählen.

Aus dem Code

ui.inspect_show(true);

Für ein Debug-Menü in deiner eigenen App.

Ein Overlay in jedem Fenster.

Das Widget unter dem Mauszeiger bekommt einen orangefarbenen Rahmen und ein Etikett mit Art, ID, Beschriftung, Größe und Zustand. Das ausgewählte Widget ist blau umrandet. Das Overlay wird nach deiner App gezeichnet, außerhalb ihrer Zeichenlisten. So bleiben die Neuzeichnungsbereiche deiner App ihre eigenen.

Ein Werkzeugfenster mit vier Tabs.

Das Fenster des Inspektors nimmt sich nie von selbst die Tastatur und taucht nie in seinem eigenen Baum, Overlay oder Pick auf. Seine Selektorzeile lässt sich direkt in ein Testskript kopieren.

Das Aussehen im laufenden Betrieb ändern.

In einem Entwicklungs-Build bearbeitet der Inspektor die laufende App über das, was schon da ist: keine API, die du aufrufen musst, und keine Zustandsstruktur, an die du dich halten musst. Probier einen anderen Stil, den Dunkelmodus oder hohen Kontrast, einen Akzent, eine Sprache, eine Skalierung, rundere Ecken oder eine andere Schrift aus und sieh das Ergebnis sofort.

  • Jede Änderung ist markiert, mit eigenem Reset-Button und einer Liste alter und neuer Werte.
  • Rückgängig und Wiederholen, auch für einen ganzen Slider-Zug als einen Schritt.
  • Speichere deine Änderungen als Theme-Datei, die die App laden kann.
  • Kopier, was du geändert hast, als Theme-Zeilen und als Code.
  • Operate klickt, zieht, tippt oder setzt einen Wert am ausgewählten Widget, als Eingabe. Die Werte deiner App werden nie hinter ihrem Rücken geschrieben.

Vom Widget zu deinem Code.

Der Tab „Widgets“ nennt Datei und Zeile, in der deine App das ausgewählte Widget erzeugt hat. Open in editor startet VS Code, CLion oder den Editor deiner Wahl an dieser Zeile. Ein zusammengesetztes Widget wie ein Zahlenfeld oder ein Menü meldet deinen Aufruf, nicht den inneren der Bibliothek.

Release-Builds lassen das komplett weg. Sie enthalten also keine Dateipfade und führen denselben Code aus wie ohne diese Funktion. Der Start des Editors folgt dem Berechtigungsmanifest deiner App, wie jedes andere Programm, das sie startet.

# der Tab „Widgets“ im Inspektor
Kind      radio
Label     Green
Selector  radio:"Green"
Source    apps/gallery/main.rs:215
          [ Open in editor ]

# dein Editor, einmal festgelegt
jfgui_EDITOR="code -g {file}:{line}"

Getestet wie alles andere.

Der Inspektor läuft auch headless in .uis-Testskripten: öffnen, picken, auswählen, Overlay und Selektor prüfen, das Aussehen ändern und die Änderung zurücknehmen. Ein Skript kann sogar beweisen, dass ein geschlossener Inspektor überhaupt nichts verändert hat.

Mit Hot Reload behält der Inspektor Tab, Optionen und Auswahl über jeden Neubau hinweg. Schlägt ein Build fehl, läuft die alte Version weiter, und der Fehler erscheint oben im Inspektor.

inspect arm
key f12                         # das Tastenkürzel öffnet ihn
inspect pick
click "Standard"                # wählt aus, die App merkt nichts
inspect expect selected button:"Standard"
inspect set radius 8
inspect expect changes 1
inspect undo
key f12                         # wieder geschlossen
inspect expect same              # Byte für Byte wie vorher
inspect expect idle              # und seitdem keine Arbeit
