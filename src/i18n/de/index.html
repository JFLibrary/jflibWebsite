#![no_std]

Kein GUI-Framework darunter. Alles aus einer Hand.

Renderer, Widgets, Bildcodecs, Netzwerk und Plattformschicht stecken alle in dieser Bibliothek, aufgebaut auf core und alloc von Rust. Du stellst dir kein Fenster-Crate, keine Event-Loop und kein UI-Crate zusammen, wie es egui-Apps mit eframe tun: Eine Abhängigkeit, jflib, ist der ganze Stack. Schreib auch deine App no_std. Braucht sie ein Crate, das std verwendet, schalte das Feature std ein, dann lässt sich jedes Crate linken. Nur keine zweite Fensterschleife einbauen und keine Async-Runtime auf dem UI-Thread laufen lassen: JFLib hat beides schon.

Eine ganze App passt auf einen Bildschirm.

// src/lib.rs
#![no_std]
#![deny(unsafe_code)]

extern crate alloc;
use jflib::{style, ui};
use ui::*;

const DESC: AppDesc = AppDesc {
    title: "Hello JFLIB",
    flags: AF_RESIZABLE,
    w: 480,
    h: 300,
    min_w: 320,
    min_h: 240,
    ..AppDesc::NONE
};

#[derive(Default)]
struct Counter {
    clicks: u32,
}

impl App for Counter {
    fn frame(&mut self, ui: &mut Ui) {
        ui.box_begin(0, BOX_V | pad(24), 12);
        ui.text(TS_TITLE, "Hello JFLIB!");
        ui.text(TS_BODY, &alloc::format!("Clicks: {}", self.clicks));
        if ui.accent_button(100, "Click me") & EV_ACT != 0 {
            self.clicks += 1;
        }
        if ui.button(101, "Reset") & EV_ACT != 0 {
            self.clicks = 0;
        }
        ui.box_end();
    }
}

ui::main!(ui::launch(&DESC, Counter::default(), &style::STYLE));
