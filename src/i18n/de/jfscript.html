In Entwicklung

JFScript. Verlässliche Skripte.

Eine kleine Skriptsprache für Apps, die mit JFLib gebaut sind. Skripte werden zu Bytecode kompiliert und laufen in einer Sandbox mit harten Grenzen. Sie liefern auf jedem Rechner dasselbe Ergebnis bis aufs letzte Bit, und sie können an jeder Stelle pausieren und später weiterlaufen. Heute betreibt JFScript die simulierten Server in JFNetworker.

JFScript ist noch in Entwicklung. Die Sprache, ihre Bibliothek und die Rust-API können sich noch ändern, bevor JFScript eigenständig veröffentlicht wird.

Auf den ersten Blick vertraut.

Wenn du schon JavaScript, Lua oder Python geschrieben hast, kannst du JFScript lesen. Es hat Funktionen und Closures, Listen und Maps, try und catch und Module über import. Maps behalten ihre Reihenfolge, Ganzzahlen bleiben Ganzzahlen, und Text zählt Zeichen, nicht Bytes.

Jedes Skript bekommt eine Standardbibliothek mit: Text, Listen, Maps, Bytes, Mathematik und JSON.

// die Teile eines Anfragepfads
let parts = "/users/42/posts".split("/")
  .filter(fn(p) { return len(p) > 0 })
let id = int.parse(parts[1]) ?? 0      // 42

// Datensätze, stabil sortiert
let jobs = [{n: "b", prio: 2}, {n: "a", prio: 1}]
jobs.sort(fn(x, y) { return x.prio - y.prio })
print(jobs.map(fn(j) { return j.n }).join(", "))

// JSON behält die Reihenfolge von Maps
let t = json.encode({id: 7, load: 0.5})
print("{:>4}|{:.2}".format(id, 0.5))    //   42|0.50

// dieselben Bits auf jedem Rechner
let load = 100 + 50 * math.sin(2 * math.pi * 3 / 24)
let shard = "user:42".hash() % 8

Was es anders macht.

Deterministisch

Keine Uhr, kein Zufall und Gleitkomma in Software. Ein Skript liefert dieselben Bits unter Windows, Linux, Android und im Browser.

In der Sandbox

Jede Anweisung kostet Treibstoff. Speicher, Stack und Aufruftiefe haben harte Grenzen. Eine Endlosschleife oder eine riesige Liste beendet also einfach den Lauf.

Pausierbar

Lass ein Skript in Abschnitten beliebiger Größe laufen, und du bekommst dasselbe Ergebnis wie in einem Stück. Eine ganze VM lässt sich mitten in einem Lauf klonen.

Nur deine Namen

Ein Skript erreicht nur die Funktionen, die der Host ihm gibt. Gib dem Compiler deine Liste von Namen, dann ist ein falsch geschriebener Name schon vor dem Lauf ein Fehler, mit Vorschlag.

Exakte Mathematik

Die Mathefunktionen sind fdlibm auf Software-Gleitkomma: Fehler unter einem ulp, und exakt, wo sich das Ergebnis exakt darstellen lässt.

Editor-Unterstützung eingebaut

Vervollständigung, Hover, Signaturen, Gehe zu Definition, Referenzen, Umbenennen, Faltung, eine Gliederung und ein Formatierer, auch bei halb getipptem Code.

Mit wenigen Zeilen Rust eingebettet.

Kompilier den Quelltext, leg eine VM mit ihren Grenzen an und lass sie mit so viel Treibstoff pro Abschnitt laufen, wie du willst. Dein Host beantwortet die Funktionen, die das Skript per Name aufruft. Werte, die länger leben als ein Lauf, werden festgepinnt, und ein veralteter Wert führt zu einem Fehler statt zu einem Absturz.

JFNetworker macht aus Treibstoff simulierte CPU-Zeit: Ein Serverskript in einem Labor kostet Zeit wie echter Code auf einem echten Rechner.

let prog = script::compile_named("server.jfs", src)?;
let mut vm = Vm::new(&prog, Limits::default());
loop {
    match vm.run(&mut host, 10_000) {   // Treibstoff pro Abschnitt
        Status::Done(_) => break,
        Status::Yielded => continue,
        Status::Error(e) => { log(&e.to_string()); break }
    }
}
let req = vm.new_str("GET /")?;
vm.call("on_request", &[req])?;

Ein Runner für die Kommandozeile.

jfs führt ein Skript aus, so wie python file.py eine Python-Datei ausführt. Es prüft Skripte, ohne sie auszuführen, führt die test_*-Funktionen von Testdateien aus, geht in einem Konsolen-Debugger Schritt für Schritt durch den Code und lässt Timer auf einer virtuellen Uhr mit festem Zufalls-Seed laufen.

Ein Skript, das nur die Standardbibliothek, print, log und Timer nutzt, läuft in jfs und in JFNetworker gleich.

jfs hello.jfs Anna Ben
jfs -e "print([3, 1, 2].sort())"
jfs --check hello.jfs
jfs --test tests/*.jfs
jfs --debug app.jfs
jfs --virtual-time --seed 7 sim.jfs

Module ohne Magie.

import ist eine ganz normale Funktion. Sie gibt die Namen der obersten Ebene einer anderen Datei als Map zurück, ohne die privaten, die mit einem Unterstrich beginnen. Jede Datei läuft einmal pro VM, und ihre Funktionen sehen weiter ihre eigenen globalen Variablen.
